ACERO DIGITAL MARKETING — BRAND GOVERNANCE
Document 4b — companion to the Brand Guidelines deck (Document 4a) and the Project Charter (Document 1)
Version 2.0

===================================================================
1. PURPOSE
===================================================================
This file is the enforcement layer for the Acero Brand Guidelines (35-slide
deck). The deck defines the system — voice, color, type, marks, application.
This file defines who owns it, how it's allowed to change, and which rules
are non-negotiable versus adaptable. Upload both files to Project Knowledge
together; they are meant to be read as one unit.

===================================================================
2. OWNERSHIP & DECISION RIGHTS
===================================================================
- Brand decisions are owned by whoever holds the Brand/Creative Lead role.
- Until that role is formally named, decision rights default to the
  Organization Owner.
- Any team member can PROPOSE a change. Only the Brand/Creative Lead (or
  Owner, until named) can RATIFY one.
- Client account teams may request client-specific exceptions (e.g., a
  client's own brand overlay on co-branded material) — exceptions require
  sign-off from the Brand/Creative Lead and must be logged under Section 5.

===================================================================
3. WHAT IS FIXED VS. ADAPTABLE
===================================================================
FIXED (never override without a ratified version change):
- The core palette (per Brand Guidelines deck v2, Sections 17-25): White
  #FFFFFF (canvas), Brand Blue #164EBD (signal), Navy #0A1533 (foundation),
  plus their full tint systems (Blue 700/500/400/300/100, Navy 700/500/300/100,
  Slate 900/700/500/400/200/100, Sky 500/400/300/200/100) and the functional
  status colors (success #1E9E63, caution #C98A12).
- The application rules from deck Section 39: Navy for dark cover/divider
  treatment only; White/Slate for all content sections; Brand Blue reserved
  for CTAs, key numbers, and active states, never body copy or a full-bleed
  background; one accent color per section; Blue+Sky pairing is
  backgrounds-only, never competing text colors.
- Brand voice principles (confident, consultative, short/declarative,
  rule-of-three, no filler) and the vocabulary Use/Avoid list.
- The Standard Content Architecture (Problem -> What's Included -> 4-Step
  Process -> Expected Results -> Example Outcome -> Why Acero -> Who It's
  For) for full-length client-facing content.
- The compliance rules inherited from the Organization Instructions —
  brand guidance NEVER overrides a compliance rule. If the two conflict,
  compliance wins, full stop.

ADAPTABLE (may flex with sign-off, without a version bump):
- Specific imagery choices, as long as they follow the Photography &
  Imagery Direction (deck Section 27).
- Social post copy variations, layout choices within the grid principles.
- Minor wording of supporting taglines (deck Section 15), as long as the
  primary tagline is unchanged.

===================================================================
5. CHANGE REQUEST PROCESS
===================================================================
1. Propose: describe the change and which deck section it affects.
2. Check against Section 3 above — is this Fixed or Adaptable?
   - Adaptable: Brand/Creative Lead can approve directly, no version bump.
   - Fixed: requires a version bump (see Section 6) and updates to both
     the deck and this file before it's considered active.
3. Log it: add a line to the change log (Section 7) regardless of size.
4. If the change affects anything already encoded in the Organization
   Instructions (see Section 8), update those too in the same change —
   the two must never drift out of sync.

===================================================================
6. VERSIONING POLICY
===================================================================
- Version format: v[major].[minor] — e.g., v1.0, v1.1, v2.0.
- Minor bump (v1.X): adaptable changes accumulated, or a Fixed-category
  clarification that doesn't change the actual rule.
- Major bump (v2.0): any change to the core palette, the primary logo
  (once one exists), the primary tagline, or the brand voice principles.
- Every major bump requires re-ratifying the affected deck sections and
  re-issuing this governance file with an updated version number.
- Skills that depend on brand rules (`acero-brand-voice-style`,
  `acero-brand-governance-auditor`) should be reviewed after any bump.

===================================================================
8. RELATIONSHIP TO ORGANIZATION INSTRUCTIONS
===================================================================
The Organization Instructions (Team/Enterprise admin setting, 3,000-char
limit) carry a condensed, always-on version of the Fixed rules from
Section 3 — palette hex codes, type system, and the logo status flag —
because those apply broadly enough to earn a place in every conversation
org-wide. Everything else (the full rationale, the Adaptable rules, the
application mockups, this governance process) stays here and in the deck,
referenced rather than repeated. If you update the Fixed rules here, the
Organization Instructions text must be updated in the same change (see
Section 5, step 4) — that merged, current version is maintained as its
own deliverable alongside this file.
